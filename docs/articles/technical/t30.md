# Win11 配置 SSH 免密登录 Linux 完整教程

通过 SSH 密钥认证，可以在 Windows 11 上登录 Linux 服务器，而不必每次都输入 Linux 账号密码。这里的“免密”通常指免输账号密码；如果为私钥设置了口令，首次使用或密钥未加载到代理时仍可能需要输入私钥口令。

本文使用 Windows 11 自带的 OpenSSH 客户端和 Linux 默认的 `~/.ssh/authorized_keys` 配置。示例中的 `用户名`、服务器地址和端口请替换为自己的实际值。

## 一、确认 Windows 已安装 OpenSSH 客户端

打开 PowerShell，运行：

```powershell
ssh -V
```

如果能看到 OpenSSH 版本信息，说明客户端已安装。如果提示找不到 `ssh` 命令，可以打开 **设置 → 系统 → 可选功能 → 查看功能**，搜索并安装 **OpenSSH 客户端**，安装后重新打开 PowerShell。

## 二、在 Windows 上生成 SSH 密钥

在 PowerShell 中执行：

```powershell
ssh-keygen -t ed25519 -C "win11-to-linux"
```

出现保存位置提示时，按 Enter 使用默认路径：

```text
C:\Users\你的 Windows 用户名\.ssh\id_ed25519
```

接着会提示输入密钥口令（passphrase）。建议设置口令以保护私钥；如果希望每次连接都不再输入口令，可以在提示时直接按两次 Enter。口令不是 Linux 登录密码。

生成后会有两个文件：

- `id_ed25519`：私钥，只保存在自己的 Windows 电脑上，切勿发送给他人或复制到服务器。
- `id_ed25519.pub`：公钥，可以添加到允许登录的 Linux 账号中。

如果默认路径下已经存在密钥，`ssh-keygen` 会询问是否覆盖。覆盖会使依赖旧密钥的连接失效；不确定时不要覆盖，可以输入其他文件名，例如 `id_ed25519_linux`。

## 三、把公钥添加到 Linux 账号

### 方法一：通过 PowerShell 发送公钥

将下面命令中的 `用户名` 和 `服务器地址` 替换为 Linux 账号名和服务器 IP 或域名：

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub" | ssh 用户名@服务器地址 "umask 077 && mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
```

例如：

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub" | ssh dev@192.0.2.10 "umask 077 && mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
```

首次连接时，SSH 可能会询问是否信任服务器主机密钥。确认服务器地址和指纹无误后输入 `yes`。随后按提示输入一次 Linux 账号密码。命令会将 Windows 公钥追加到该账号的 `authorized_keys` 文件，并设置 SSH 要求的目录和文件权限。

如果服务器 SSH 端口不是默认的 22，增加 `-p 端口号` 参数，例如：

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub" | ssh -p 2222 dev@192.0.2.10 "umask 077 && mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
```

### 方法二：手动复制公钥

在 Windows 上显示公钥：

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
```

复制完整的一行内容。先使用账号密码登录 Linux，然后在 Linux 终端执行：

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
nano ~/.ssh/authorized_keys
```

将公钥粘贴为单独的一行，保存退出，再执行：

```bash
chmod 600 ~/.ssh/authorized_keys
```

确认公钥完整且没有被拆成多行。`authorized_keys` 中可以有多把公钥，每把公钥占一行。

## 四、验证密钥登录

在 Windows PowerShell 中运行：

```powershell
ssh 用户名@服务器地址
```

如果使用非默认端口：

```powershell
ssh -p 2222 用户名@服务器地址
```

成功进入 Linux shell 即表示配置完成。若私钥设置了口令，连接时要求输入的是私钥口令，而不是 Linux 账号密码。

## 五、配置登录别名（可选）

如果经常连接同一台服务器，可以编辑 Windows 用户目录下的 SSH 配置文件：

```powershell
notepad "$env:USERPROFILE\.ssh\config"
```

文件不存在时，记事本会提示新建。添加以下内容并按实际情况修改：

```sshconfig
Host my-linux
    HostName 192.0.2.10
    User dev
    Port 22
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
```

之后可以使用别名登录：

```powershell
ssh my-linux
```

## 常见问题

### 仍然要求输入 Linux 账号密码

1. 确认公钥添加到了正在登录的 Linux 用户的 `~/.ssh/authorized_keys`，不是其他用户或 `root` 的目录。
2. 在 Linux 上检查权限和文件所有者：

   ```bash
   chmod 700 ~/.ssh
   chmod 600 ~/.ssh/authorized_keys
   chown -R "$USER":"$(id -gn)" ~/.ssh
   ```

3. 确认连接的用户名、服务器地址和端口正确。
4. 检查 Linux SSH 服务端是否启用了公钥认证。服务端配置通常在 `/etc/ssh/sshd_config`，需确认 `PubkeyAuthentication yes`，并确认 `AuthorizedKeysFile` 指向预期文件。修改服务端配置后，按发行版使用 `sudo systemctl reload ssh` 或 `sudo systemctl reload sshd`；操作前应确认配置有效并保留现有连接，避免锁住远程访问。
5. 使用详细日志定位客户端实际使用的密钥：

   ```powershell
   ssh -v 用户名@服务器地址
   ```

### 提示 `Permission denied (publickey)`

核实 `authorized_keys` 中的内容与 Windows `.pub` 文件完全一致；确认没有把私钥 `id_ed25519` 当作公钥复制；再检查 Linux 用户目录及 `.ssh` 目录权限。若服务器启用了 SELinux，也可检查 SSH 相关安全上下文。

### 非默认端口连接失败

确认使用了正确的 `-p 端口号`，同时确认服务器防火墙和云平台安全组允许该端口的入站连接。SSH 配置文件中的端口字段使用 `Port`。

## 安全注意事项

- 私钥 `id_ed25519` 等同于登录凭据，应保存在受信任的电脑上；只上传 `.pub` 公钥。
- 为私钥设置口令可以降低私钥文件泄露后的风险。若要避免重复输入口令，可进一步配置 Windows 的 `ssh-agent`，但不要因此把私钥口令写进脚本或配置文件。
- 确认密钥登录可用前，不要关闭服务器的密码认证或现有远程登录方式，以免配置错误后无法登录。
- 不要盲目接受陌生或突然变化的服务器主机密钥指纹；应通过可信渠道核对服务器身份。
