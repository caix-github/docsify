# 处理 IDEA 控制台乱码

在 IntelliJ IDEA 中运行 Java 程序时，如果控制台出现中文乱码，通常是因为程序输出使用的字符集与 IDEA 控制台解码时使用的字符集不一致。

例如，程序或系统使用 GBK 编码输出中文，而控制台按照 UTF-8 解码，就可能出现类似下面的情况：

```text
���й��ַ���
```

## 解决方案

可以在 IDEA 的运行配置中为 JVM 指定默认字符集为 GBK。

1. 打开 **设置**，进入 **构建、执行、部署**。
2. 展开 **构建工具**，选择 **Maven**。
3. 找到 **运行程序**，在 **虚拟机选项** 中填入：

```text
-Dfile.encoding=GBK
```

4. 点击 **应用**，再点击 **确定**。
5. 重新运行程序，检查控制台中的中文是否已经恢复正常。

设置完成后，运行配置中的虚拟机选项应类似下面这样：

```text
-Dfile.encoding=GBK
```

## 为什么可以解决乱码

`file.encoding` 是 Java 虚拟机使用的默认字符集。部分文本读写、日志输出以及第三方库在没有明确指定字符集时，会读取这个默认值。

通过设置：

```text
-Dfile.encoding=GBK
```

可以让当前 Java 进程优先使用 GBK 处理默认字符编码，从而与使用 GBK 输出内容的控制台或旧项目保持一致。

## 需要注意的地方

- 这个配置只对当前运行配置生效，不会修改源文件本身的编码。
- 如果项目实际使用 UTF-8，就不要盲目设置为 GBK，应优先统一项目、终端和文件的编码。
- 读取或写入文件时，建议在代码中显式指定字符集，不要完全依赖 `file.encoding`。

例如使用 Java 读写文件时，可以明确指定编码：

```java
Files.readString(path, StandardCharsets.UTF_8);
Files.writeString(path, content, StandardCharsets.UTF_8);
```

如果乱码仍然存在，还需要检查以下配置：

- IDEA 的文件编码设置是否统一为 UTF-8 或 GBK；
- Maven 编译插件中的源码编码和资源编码是否正确；
- Windows 控制台当前代码页是否与程序输出编码一致；
- 日志框架或第三方库是否单独指定了编码。

## 总结

处理 IDEA 控制台中文乱码时，可以先在对应的 Maven 运行配置中设置：

```text
-Dfile.encoding=GBK
```

然后重新运行程序验证效果。如果项目正在逐步迁移到 UTF-8，更推荐从源文件、编译配置、日志输出和运行环境几个环节统一编码，而不是长期依赖单独修改默认字符集。
