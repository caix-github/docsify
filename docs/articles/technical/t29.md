# Xshell 常用命令与前端部署示例

Xshell 是常见的 SSH 客户端，用来连接远程服务器并执行命令。成功登录 Linux 服务器后，终端里输入的命令通常由远程服务器执行；上传和下载文件则可以使用 Xftp、Xshell 的文件传输功能，或本机的 `scp` 命令。

以下示例以 Linux 服务器和 Nginx 托管静态前端为例。命令中的用户名、域名和目录请替换成自己的配置；执行删除、改权限等操作前，先确认目标路径和当前账号。

## 连接前准备

新建 Xshell 会话时填写服务器的 IP 或域名、SSH 端口（通常为 `22`）和登录用户名。连接后根据提示使用密码或 SSH 密钥完成身份验证。

登录后先确认当前账号与机器信息：

```bash
whoami
hostname
pwd
```

如果连接失败，检查服务器地址、端口、安全组或防火墙规则、账号和密钥权限；不要把私钥或密码粘贴到共享聊天或公开文档中。

## 常用命令

### 目录与文件

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `pwd` | 显示当前目录 | `pwd` |
| `ls -lah` | 查看文件和隐藏文件，显示大小及权限 | `ls -lah /var/www` |
| `cd` | 切换目录 | `cd /var/www` |
| `mkdir -p` | 创建目录及所需的父目录 | `mkdir -p /var/www/my-frontend` |
| `cp -r` | 复制目录或文件 | `cp -r dist backup-dist` |
| `mv` | 移动或重命名文件 | `mv app.conf app.conf.bak` |
| `find` | 按条件查找文件 | `find /var/www -name index.html` |

`rm` 会直接删除文件，执行前务必核对路径。特别是 `rm -rf`，不要对不确定的路径或变量使用：

```bash
rm -i old-file.txt
```

### 查看文件和日志

```bash
cat app.conf            # 输出整个小文件
less app.conf           # 分页查看，按 q 退出
tail -n 100 app.log     # 查看最后 100 行
tail -f app.log         # 持续跟踪日志，按 Ctrl+C 退出
grep -n "error" app.log # 查找包含 error 的行并显示行号
```

### 系统资源与进程

```bash
df -h             # 查看磁盘空间
du -sh /var/www/* # 查看目录大小
free -h           # 查看内存
top               # 实时查看进程和资源占用，按 q 退出
ps -ef            # 查看进程
```

### 权限与服务

```bash
chmod 644 index.html         # 文件常见权限：所有者可读写，其他用户只读
chmod 755 /var/www/my-frontend # 目录常见权限：所有者可写，其他用户可读和进入
sudo systemctl status nginx  # 查看 Nginx 服务状态
sudo nginx -t                # 检查 Nginx 配置语法
sudo systemctl reload nginx  # 平滑重新加载 Nginx 配置
```

`sudo` 是否可用取决于服务器账号权限。不要为图方便把站点目录设置为所有用户可写；应根据服务器上的 Nginx 运行用户和部署账号配置最小必要权限。

## 示例：部署一个前端站点

假设项目在本机开发完成，生产构建产物输出到 `dist` 目录，服务器已安装 Nginx，站点使用 `www.example.com`。域名、项目构建命令、输出目录和服务器目录应以实际项目为准。

### 1. 在本机构建

在项目目录中安装依赖并执行生产构建：

```bash
npm ci
npm run build
```

确认 `dist` 中存在 `index.html` 和打包后的静态资源。若项目使用不同的构建命令或输出目录，请按项目配置调整。

### 2. 上传构建产物

使用 Xftp（或其他 SFTP 客户端）连接同一台服务器，将本地 `dist` **目录中的文件和子目录**上传到服务器的 `/var/www/my-frontend`。首次部署时可先通过 Xshell 创建目录：

```bash
sudo mkdir -p /var/www/my-frontend
```

上传后检查目录内容：

```bash
ls -lah /var/www/my-frontend
```

确认其中能看到 `index.html`，而不是只看到一个尚未展开的 `dist` 子目录。若服务器策略不允许部署账号写入该目录，应按管理员规定使用有权限的发布目录或部署流程，不要直接放宽为全员可写。

自动部署脚本例子

```
#!/bin/bash
set -euo pipefail

: '
========================================================================
脚本名称：前端自动部署脚本 deploy.sh
功能：
  1.本地执行前端打包，将dist产物压缩上传至服务器
  2.部署前自动备份服务器旧版本代码
  3.自动清理旧备份，只保留指定最大备份数量
  4.临时压缩包上传至服务器/tmp目录，部署完毕自动清理
变量说明：
  FRONT_PROJECT_NAME：项目业务标识，备份包文件名前缀、日志打印，可代表环境
  SERVER_DEPLOY_DIR：服务器nginx下实际部署文件夹名称，可与项目标识不同
  SERVER_PATH：完整部署路径，由 SERVER_DEPLOY_DIR 自动拼接，无需手动修改
注意事项：
  1.建议配置SSH免密登录，避免重复输入密码
  2.回滚脚本 rollback.sh 中 FRONT_PROJECT_NAME、SERVER_DEPLOY_DIR 必须和本脚本保持一致
  3.所有业务配置统一修改脚本头部变量区即可，不需要改动下方业务逻辑代码
========================================================================
'

# =====================【部署配置 - 全部变量集中在这里修改】=====================
# 服务器IP地址
SERVER_IP="192.168.126.90"
# 服务器SSH登录用户名
SERVER_USER="root"
# 服务器SSH端口
SERVER_PORT="22"

# 本地打包产物目录，vue/react项目一般是 ./dist
LOCAL_DIST="./dist"
# 【项目标识名称】：用于备份包文件名前缀、日志输出，和服务器部署目录可以不一样
FRONT_PROJECT_NAME="dms"
# 【服务器部署目录名】：nginx html下实际存放代码的文件夹名称，可与项目名不同
SERVER_DEPLOY_DIR="lgxmop-sit"
# 本地执行的打包命令，可改为 npm run build / yarn build / pnpm build
LOCAL_BUILD_CMD="npm run sit"

# 服务器部署完整路径，不需要修改，由上面变量拼接
SERVER_PATH="/usr/local/nginx/html/${SERVER_DEPLOY_DIR}"
# 服务器备份文件存放根目录
BACKUP_BASE="/usr/local/nginx/html/backup"
# 备份最大保留版本数量，超过此数量自动删除最旧备份
MAX_BACKUP_COUNT=3

# 本地临时压缩包文件名（脚本执行当前目录生成）
LOCAL_TMP_TAR="./${FRONT_PROJECT_NAME}_dist.tar.gz"
# 服务器端临时压缩包存放路径，放在/tmp，服务器重启自动清理
SERVER_TMP_FILE="/tmp/${FRONT_PROJECT_NAME}_dist.tar.gz"
# ==============================================================================

echo "===== 开始部署前端项目【${FRONT_PROJECT_NAME}】====="

# 1. 本地执行项目打包
echo "🔨 执行本地打包命令：${LOCAL_BUILD_CMD}"
${LOCAL_BUILD_CMD}

# 校验打包产物dist目录是否生成
if [ ! -d "${LOCAL_DIST}" ]; then
  echo "❌ 打包失败，产物目录 ${LOCAL_DIST} 不存在，请检查打包命令"
  exit 1
fi
echo "✅ 本地打包完成"

# 2. 将dist目录打包为本地临时压缩包
echo "📦 本地打包dist目录：${LOCAL_TMP_TAR}"
rm -f "${LOCAL_TMP_TAR}"
tar -zcf "${LOCAL_TMP_TAR}" -C "${LOCAL_DIST}" .

# 3. 上传压缩包到服务器 /tmp 临时目录
echo "🚀 上传压缩包到服务器临时路径：${SERVER_TMP_FILE}"
scp -P "${SERVER_PORT}" "${LOCAL_TMP_TAR}" "${SERVER_USER}@${SERVER_IP}:${SERVER_TMP_FILE}"

# 4. 服务器远程执行：备份旧版本 + 解压新版本 + 清理过期备份
echo "🔧 服务器执行备份与部署更新"
ssh -p "${SERVER_PORT}" "${SERVER_USER}@${SERVER_IP}" << EOF
set -euo pipefail

# 拼接本次备份包完整文件名，备份包前缀使用项目业务标识
BACKUP_TAR_NAME="${FRONT_PROJECT_NAME}_\$(date +%Y%m%d_%H%M%S).tar.gz"
BACKUP_FULL_TAR="${BACKUP_BASE}/\${BACKUP_TAR_NAME}"

# 创建备份根目录
mkdir -p "${BACKUP_BASE}"

# 如果线上部署目录已存在，先备份旧代码
if [ -d "${SERVER_PATH}" ]; then
    echo "📑 备份线上旧版本，备份文件名：\${BACKUP_TAR_NAME}"
    cd "${SERVER_PATH}" && tar -zcf "\${BACKUP_FULL_TAR}" .
    echo "✅ 旧版本备份完成"

    # 清理过期备份：保留最新 MAX_BACKUP_COUNT 个，其余删除
    echo "🧹 清理过期备份，仅保留最新${MAX_BACKUP_COUNT}份"
    ls -1t "${BACKUP_BASE}/${FRONT_PROJECT_NAME}_"*.tar.gz 2>/dev/null | tail -n +$((MAX_BACKUP_COUNT +1)) | xargs -r rm -f
fi

# 确保部署目录存在
mkdir -p "${SERVER_PATH}"
# 清空部署目录旧文件
rm -rf "${SERVER_PATH:?}"/*
# 解压新版本代码
echo "📂 解压新版本代码至部署目录 ${SERVER_PATH}"
tar -zxf "${SERVER_TMP_FILE}" -C "${SERVER_PATH}"

# 删除服务器临时压缩包
rm -f "${SERVER_TMP_FILE}"
EOF

# 5. 删除本地临时压缩包
echo "🗑️ 删除本地临时压缩包 ${LOCAL_TMP_TAR}"
rm -f "${LOCAL_TMP_TAR}"

echo ""
echo "🎉 项目【${FRONT_PROJECT_NAME}】部署成功！"
echo "💡 如需回滚，请执行回滚脚本，输入备份包名称"

```

自动回滚脚本例子

```
#!/bin/bash
set -euo pipefail

: '
========================================================================
脚本名称：前端版本回滚脚本 rollback.sh
功能：
  1.拉取服务器当前项目全部备份列表，展示带序号的备份清单
  2.输入序号选择要回滚的版本，二次确认后执行回滚
  3.回滚前自动备份当前线上版本，防止回滚出错
  4.回滚产生的临时备份同样遵循最大备份数量限制
注意事项：
  1. FRONT_PROJECT_NAME、SERVER_DEPLOY_DIR 必须与 deploy.sh 完全一致
  2.备份包是按 FRONT_PROJECT_NAME 作为前缀过滤，不要修改项目标识
  3.建议配置SSH免密登录
========================================================================
'

# =====================【回滚配置，必须和deploy.sh配置保持完全一致】=====================
# 服务器IP地址
SERVER_IP="192.168.126.90"
# 服务器SSH登录用户名
SERVER_USER="root"
# 服务器SSH端口
SERVER_PORT="22"

# 【项目标识名称】备份包文件名前缀，日志标识，与部署脚本保持一致
FRONT_PROJECT_NAME="dms"
# 【服务器部署目录名】nginx下实际项目文件夹，可与项目名不同
SERVER_DEPLOY_DIR="lgxmop-sit"

# 服务器部署完整路径，无需修改，由变量拼接
SERVER_PATH="/usr/local/nginx/html/${SERVER_DEPLOY_DIR}"
# 服务器备份文件存放根目录
BACKUP_BASE="/usr/local/nginx/html/backup"
# 备份最大保留版本数量，和部署脚本保持一致
MAX_BACKUP_COUNT=3
# ======================================================================================

echo "===== 前端项目回滚工具【${FRONT_PROJECT_NAME}】 ====="
echo "📍服务器部署目录：${SERVER_PATH}"
echo "📂 备份文件存放目录：${BACKUP_BASE}"
echo "----------------------------------------------------------------------"

# 获取服务器该项目全部备份，按修改时间从新到旧排序
BACKUP_LIST=$(ssh -p "${SERVER_PORT}" "${SERVER_USER}@${SERVER_IP}" "ls -1t ${BACKUP_BASE}/${FRONT_PROJECT_NAME}_*.tar.gz 2>/dev/null")

if [[ -z "${BACKUP_LIST}" ]];then
  echo "❌ 没有找到项目【${FRONT_PROJECT_NAME}】任何备份文件，无法执行回滚！"
  exit 1
fi

# 将备份列表加载到数组
mapfile -t backup_arr <<< "${BACKUP_LIST}"

# 打印带序号备份列表
echo "📋 当前可用备份版本列表(序号越小版本越新):"
for idx in "${!backup_arr[@]}"; do
  file_name=$(basename "${backup_arr[$idx]}")
  echo "    $((idx+1)). ${file_name}"
done
echo "----------------------------------------------------------------------"

read -p "请输入要回滚版本的数字序号: " sel_idx

# 校验输入是否为数字
if ! [[ "${sel_idx}" =~ ^[0-9]+$ ]];then
  echo "❌ 输入无效，请输入数字序号，脚本退出"
  exit 1
fi

array_index=$((sel_idx - 1))
# 判断序号是否越界
if [[ ${array_index} -lt 0 || ${array_index} -ge ${#backup_arr[@]} ]];then
  echo "❌ 输入序号不在列表范围内，脚本退出"
  exit 1
fi

SELECTED_BACKUP_FULL_PATH="${backup_arr[$array_index]}"
SELECTED_BACKUP_NAME=$(basename "${SELECTED_BACKUP_FULL_PATH}")

echo "✅ 选中回滚备份包：${SELECTED_BACKUP_NAME}"
read -p "⚠️警告：回滚会覆盖当前线上代码！确认执行回滚？(y/N): " confirm_input
if [[ "${confirm_input}" != "y" && "${confirm_input}" != "Y" ]];then
  echo "已取消回滚操作，脚本退出"
  exit 0
fi

# 远程服务器执行回滚逻辑
ssh -p "${SERVER_PORT}" "${SERVER_USER}@${SERVER_IP}" << EOF
set -euo pipefail

# 校验选中备份文件真实存在
if [ ! -f "${SELECTED_BACKUP_FULL_PATH}" ]; then
  echo "❌ 错误：备份文件【${SELECTED_BACKUP_FULL_PATH}】不存在！"
  exit 1
fi

# 回滚之前，先备份当前正在运行的线上版本，防止回滚失误
SAFE_BACKUP_NAME="${FRONT_PROJECT_NAME}_rollback_bak_\$(date +%Y%m%d_%H%M%S).tar.gz"
SAFE_BACKUP_FULL_PATH="${BACKUP_BASE}/\${SAFE_BACKUP_NAME}"

if [ -d "${SERVER_PATH}" ]; then
  echo "📑 回滚前先备份当前线上版本：\${SAFE_BACKUP_NAME}"
  cd "${SERVER_PATH}" && tar -zcf "\${SAFE_BACKUP_FULL_PATH}" .
  # 回滚生成的备份同样执行过期清理策略
  ls -1t "${BACKUP_BASE}/${FRONT_PROJECT_NAME}_"*.tar.gz 2>/dev/null | tail -n +$((MAX_BACKUP_COUNT +1)) | xargs -r rm -f
fi

# 执行回滚解压
echo "🔄 执行回滚，恢复备份包：${SELECTED_BACKUP_NAME}"
mkdir -p "${SERVER_PATH}"
rm -rf "${SERVER_PATH:?}"/*
tar -zxf "${SELECTED_BACKUP_FULL_PATH}" -C "${SERVER_PATH}"

echo ""
echo "✅ 回滚操作完成！"
echo "📍项目【${FRONT_PROJECT_NAME}】已恢复至备份：${SELECTED_BACKUP_NAME}"
EOF
```

### 3. 配置 Nginx

在服务器的 Nginx 站点配置中添加或更新一个 `server` 配置。配置文件的具体位置因发行版和安装方式而异；常见位置包括 `/etc/nginx/conf.d/` 下的文件，或 `/etc/nginx/sites-available/` 下的站点文件。

```nginx
server {
    listen 80;
    server_name www.example.com;

    root /var/www/my-frontend;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

`try_files` 的回退路径适用于使用前端路由的单页应用：当请求路径不是实际静态文件时，交由 `index.html` 启动前端路由。若项目并非单页应用，或已有反向代理、HTTPS 配置，应与现有站点配置合并，不要覆盖已有服务。

保存配置后先测试语法，再重新加载：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

仅在 `nginx -t` 显示配置测试成功后再 reload。若测试失败，依据错误信息修正配置，并再次测试；不要通过重启来绕过配置错误。

### 4. 验证访问

在浏览器打开 `http://www.example.com`，检查页面和静态资源是否正常。若域名尚未解析，可以先确认服务器的 80 端口可访问，或由管理员配置临时验证方式。

常见问题排查：

- **出现 Nginx 默认页或 403**：确认 `root` 指向的目录下有 `index.html`，并检查 Nginx 对目录和文件是否有读取权限。
- **刷新前端子路由出现 404**：检查 `location /` 中是否配置了 `try_files $uri $uri/ /index.html;`。
- **页面打开但资源 404**：检查项目的资源基础路径（base/public path）是否匹配站点部署路径，并确认上传了完整构建产物。
- **配置修改后没有生效**：先运行 `sudo nginx -t`，再确认 reload 成功；同时检查访问的域名是否命中了预期的 `server_name`。

## 发布时的注意事项

- 部署前确认构建结果和目标目录，不要把源码、开发环境配置或密钥文件当作静态产物上传。
- 更新现有站点前保留可恢复的旧版本或备份；高可用或生产环境应使用经过验证的发布流程，避免上传过程中用户读到不完整文件。
- 不要在终端命令、脚本或文章中写入真实密码、私钥、令牌或内部服务器地址。
- 服务器上的目录权限、Nginx 配置位置及服务管理方式可能因系统而异，执行前应核对当前环境。
